## Codebase Patterns
- Backend schemas in `backend/app/schemas.py`, routes in `backend/app/routes.py`, download logic in `backend/app/download_service.py`
- yt-dlp runs in ThreadPoolExecutor (not async-native), use `loop.run_in_executor(executor, ...)` for async endpoints
- Pydantic v2 with `field_validator` and `model_validate`
- Routes use slowapi rate limiter and async SQLAlchemy sessions
- VideoQuality enum in models.py: Q_360P, Q_480P, Q_720P, Q_1080P, MP3
- Frontend VideoQuality type: '360p' | '480p' | '720p' | '1080p' | 'mp3'
- Frontend DownloadRequest uses `quality: VideoQuality` (not output_format)
- Frontend QueueItem uses `quality: VideoQuality` (not format: OutputFormat)
- api.ts has `fetchPreview(url)` for POST /api/preview
- QualitySelector component: accepts `selectedQuality`, `onQualityChange`, `availableQualities?: number[]`, `disabled?: boolean`
- QualitySelector disables video resolutions when no available quality >= that resolution
- VideoPreview component: accepts `preview: PreviewResponse | null`, `isLoading: boolean`, `error: string | null`
- DownloadRequest has `quality: VideoQuality` (default Q_480P) and deprecated `output_format`
- `get_yt_dlp_options` now accepts `quality: VideoQuality` — video uses height-based format + `-c copy`, MP3 uses FFmpegExtractAudio
- `start_download` and `_run_download` accept `quality: VideoQuality` (not `output_format`)

## 2026-03-13 - US-005
- Rescaled download progress to 0-70% (was 0-100%), download finished to 70% (was 88%)
- Rescaled conversion/postprocessor progress to 70-95% (was 90-95%), finalization to 95% (was 98%)
- Added interpolation timer using threading.Timer: if no FFmpeg progress update for 5 seconds during conversion, increments 1% every 2 seconds (capped at 95%)
- Interpolation auto-starts on postprocessor "started" and stops on "finished"
- CopyStream (no re-encoding) naturally jumps from 70% to 95% quickly since postprocessor finishes fast
- Files changed: backend/app/download_service.py
- **Learnings for future iterations:**
  - Progress phases defined as class constants (DOWNLOAD_MAX=70, CONVERSION_MIN=70, CONVERSION_MAX=95) for easy tuning
  - threading.Timer with daemon=True avoids blocking process exit
  - time.monotonic() is preferred over time.time() for elapsed duration tracking

## 2026-03-13 - US-010
- Created `useSmoothedProgress` hook: smooths raw progress values with two strategies
  - Large jumps (>10%): animates incrementally at 1% per 100ms to the target value
  - Stall detection: if no real update for 5 seconds during active state, interpolates +0.5%/s (capped at 95%)
  - Resets interpolation timer on each real SSE progress update
- Created `SmoothProgressBar` component wrapping the hook with configurable height, text size, and bar color
- Updated `QueueManager` to use SmoothProgressBar in renderQueueItem
- Updated `ProgressCard` to use SmoothProgressBar (replaces inline progress bar)
